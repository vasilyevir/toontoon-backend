# TOONTOON — Правки генерации: логические ошибки

Версия документа: 1.0 | Дата: 2026-06-19

Документ описывает **логические ошибки конвейера генерации** (изображения, открытки, видео)
и правки к ним. Найдено при ревью `ARCHITECTURE-GENERATION.md` v1.0 и двух рантайм-скринов чата.
Адресат — разработчик бэкенда (`/opt/gen-backend/app`) и фронта (`/opt/gen-frontend`).

## 1. Как читать документ

**Приоритеты:**
- 🔴 **P0** — ломает суть продукта, делать первым.
- 🟡 **P1** — заметно портит результат или мёртвая логика.
- 🟢 **P2** — edge-case / технический риск.

**Статусы:**
- **CONFIRMED** — баг виден в проде (на скринах) или прямо противоречит сам себе в архитектуре. Можно брать в работу.
- **BY-DOC 🔎** — вычитано из архитектурного документа; прод-код напрямую недоступен, **перед фиксом сверить с реальным файлом**.

**Каждая правка** идёт одним блоком: `>` строка с приоритетом / статусом / файлами, затем
**Симптом → Причина → Ожидаемо → Правка → Проверка**.

## 3. Чат-ассистент

### 3.1 Чат подменяет персонажа на чужой бренд

> 🔴 P0 · CONFIRMED · `routers/chat.py`, `services/gpt.py` (`_SCENE_SYSTEM`)

**Симптом.** Запрос «сделай видео со **спанчбобом**» → ответ ассистента: «Хочешь, чтобы это было веселое
видео с **Смешариками**?» — другой, никем не упомянутый мультфильм.

**Причина.** Нарушено правило `_SCENE_SYSTEM` («упомянутый персонаж должен стать главным субъектом»):
субъект не сохранён, а заменён случайным. Похоже на кривой обход копирайта — вместо «убрать бренд / переспросить»
ассистент придумал **другой копирайтный** бренд (и SpongeBob, и Смешарики — товарные знаки). Политики на
запрос копирайтных персонажей нет.

**Ожидаемо.** На копирайтного персонажа — либо мягкая замена на **дженерик-описание** («жёлтый мультяшный
морской губчатый персонаж»), либо честный отказ с предложением аналога. Никогда не подменять на другой конкретный бренд.

**Правка.** В системном промпте ассистента: (1) запрет придумывать бренды, которых не было в запросе;
(2) единая ветка «named IP → дженерик-перифраз» и для реплики чата, и для билдера промпта.

**Проверка.** «видео со спанчбобом» → в реплике нет постороннего бренда, в финальный промпт уходит дженерик.

### 3.2 Реплика чата ≠ то, что уходит в генерацию

> 🔴 P0 · CONFIRMED · `chat.py`, `gpt.py`, `content_gen.py`, `video_prompts.py`

**Симптом.** Чат говорит «Смешарики», но в `_build_freetext_storyboard` уходит исходный текст юзера
(«спанчбоб»). `strip_brands()` ловит только Pixar/Disney/DreamWorks/Ghibli — «spongebob» проходит.
Пользователю обещали одно, на вход Seedance уйдёт другое.

**Причина.** Источник истины для реплики и для промпта — разный.

**Ожидаемо.** Реплика чата и вход генератора строятся из одного нормализованного описания субъекта.

**Правка.** Единая нормализация запроса (паспорт субъекта) до развилки «реплика / генерация».
Расширить `strip_brands()` или заменить на «named-IP → дженерик» (см. 3.1).

**Проверка.** Лог финального промпта совпадает по субъекту с тем, что показал чат.

### 3.3 Смешение языков RU/EN, нет единой локали

> 🟡 P1 · CONFIRMED · `chat.py` (system prompt), фронт-строки

**Симптом.** «What would you like to create next?» (EN) → ответ по-русски → «Выберите стиль для вашего видео»
(RU), пилюли — EN. Половина UI на одном языке, половина — на другом.

**Причина.** Продукт по архитектуре — англоязычный US-рынок (все продуктовые тексты EN), но ассистент
несогласованно сваливается в язык пользователя.

**Ожидаемо.** Зафиксированная локаль продукта во всём флоу (реплики ассистента + системные строки).

**Правка.** В системном промпте `chat.py` зафиксировать язык ответов = локаль продукта; системные строки
фронта — из одного словаря локали.

**Проверка.** Любой ввод → весь флоу на одном языке.

## 4. Стили

### 4.1 6 кнопок стиля → 3 одинаковых результата, нет `realistic`

> 🟡 P1 · CONFIRMED · фронт `generate/page.tsx`, `prompt_style.map_style()`

**Симптом.** Пилюли `Pixart · Cartoon · Anime · 3D Animation · Cinematic · Fairytale`. По `map_style()`:

| Кнопка       | → пресет     |
|--------------|--------------|
| Pixart       | `3d_cartoon` |
| Cartoon      | `3d_cartoon` |
| 3D Animation | `3d_cartoon` |
| Anime        | `anime`      |
| Cinematic    | `scene_epic` |
| Fairytale    | `scene_cozy` |

**Причина.** Три кнопки (Pixart / Cartoon / 3D Animation) дают идентичный `3d_cartoon`; пресет `realistic`
не предложен. «Pixart» — бренд-метка, которую `strip_brands` всё равно вырежет.

**Ожидаемо.** Кнопки = различимые пресеты 1:1 (3d_cartoon / scene_cozy / scene_epic / anime / realistic).

**Правка.** Свести список пилюль к реальным пресетам, убрать дубли и бренд-метки.

**Проверка.** Каждая кнопка визуально отличается; `realistic` доступен.

### 4.2 В видео-флоу подставлен набор стилей от картинок

> 🟡 P1 · CONFIRMED · фронт `generate/page.tsx`, `video_prompts.py`

**Симптом.** Это видео-флоу, а пилюли `Anime / Cinematic / Fairytale`. У видео есть только
`STYLE_3D / STYLE_3D_SCENE_COZY / STYLE_3D_SCENE_EPIC` — нет `anime`/`realistic`.

**Причина.** Набор стилей картинок переиспользован в видео без учёта, что у видео другой набор якорей.
«Anime» для видео маппить не на что → стиль игнорируется/ломается.

**Ожидаемо.** Для видео — только поддерживаемые видео-стили; для картинок — свои.

**Правка.** Развести два набора стилей (image / video) на фронте; видео-путь принимает только видео-пресеты.

**Проверка.** В видео-флоу нет неподдерживаемых стилей; выбранный стиль реально влияет на видео.

### 4.3 `scene_epic` недостижим в авто-детекте free-text

> 🟡 P1 · BY-DOC 🔎 · `prompt_style.py`

**Симптом.** Авто-детект free-text даёт только `3d_cartoon` (есть живой) или `scene_cozy`. Ветки на `scene_epic` нет.

**Причина.** «Эпичные горы/море» текстом всегда падают в уютный `scene_cozy` — масштабный якорь не включается.

**Ожидаемо.** Масштабная сцена без живого субъекта → `scene_epic`.

**Правка.** Добавить детект «масштабная сцена» (mountains / ocean / canyon / эпично…) → `scene_epic`.

**Проверка.** «огромные горы на закате» (free-text) → `scene_epic`.

### 4.4 Вопрос `style` у открыток vs жёсткий `STYLE_3D`

> 🟡 P1 · BY-DOC 🔎 · `tiles_data.py`, `card_prompts.py`

**Симптом.** §5.2 архитектуры перечисляет `style` среди ключей открыток, но §8/§11 — все открытки жёстко на `STYLE_3D`.

**Причина.** Если открытка реально задаёт вопрос про стиль, ответ игнорируется → вводящий в заблуждение вопрос.

**Ожидаемо.** Либо убрать `style` из вопросов открыток, либо реально применять выбранный стиль.

**Правка.** Сверить `tiles_data.py` + `card_prompts.py`; привести вопрос и поведение в соответствие.

**Проверка.** Если вопрос есть — стиль влияет; если влиять не должен — вопроса нет.

## 5. Открытки: текст при скачивании

### 5.1 Картинку/открытку с текстом нельзя скачать (текст не вшит)

> 🔴 P0 · CONFIRMED · overlay-пайплайн, `content_gen.py`, фронт

**Симптом.** Текст-пожелание не рисуется генератором, а накладывается **CSS-слоем** поверх `<img>` на фронте.
Запекание в сам файл не реализовано. На пути «Скачать» пользователь сохраняет открытку **без поздравления**.

**Причина.** CSS-слой живёт только в приложении / по share-ссылке; в скачанном файле его нет.

**Ожидаемо.** Скачанный файл картинки/открытки содержит поздравление так же, как просмотр в приложении.

**Правка.** Запекать текст в изображение server-side (например Pillow) поверх готового файла перед отдачей
на скачивание. До реализации — честно помечать в UI, что скачивание идёт без текста.

**Проверка.** Скачать открытку с текстом → текст присутствует в файле.

> **Видео не трогаем.** Текстовый слой в видео (`video_greeting`, `morning_video`, `inspiring_video`,
> ffmpeg `drawtext`) по решению продукта **отложен** — см. раздел 9.

## 6. Вопросы тайлов

### 6.1 Нет рода / числа / возраста в кнопочных вопросах

> 🟡 P1 · BY-DOC 🔎 · `tiles_data.py`, `picture_prompts.py`, `card_prompts.py`, `gpt.py`

**Симптом.** Вопросы картинок (`animal/action/setting`, `bird/…`, `fish/…`, `place/time_of_day/detail`,
`dish/setting`) и ключи открыток не содержат **пол** и **число**; `age` есть только у `birthday`/`jubilee`.

**Причина.** «Две кошки», «котёнок» (детёныш), «дедушка», род субъекта — невыразимы кнопками
(только free-text). Это FIX-2/FIX-3/FIX-4 из `GENERATION_FIXES.md`.

**Ожидаемо.** Род/число/возраст учитываются в промпте.

**Правка.** «Паспорт субъекта» (`gender/number/age`), который GPT-билдер заполняет до подстановки
плейсхолдеров (см. §0 `GENERATION_FIXES.md`). Где уместно — добавить кнопки.

**Проверка.** «дедушка», «две кошки» → корректно отражены в промпте.

### 6.2 Пересечение тайлов `cute_animal` vs `birds`/`fish`

> 🟢 P2 · BY-DOC 🔎 · `tiles_data.py`

**Симптом.** `cute_animal` спрашивает `animal`, при этом есть отдельные `birds`/`fish`. «Попугай»/«рыбка»
в `cute_animal` уйдут в шаблон с обогащением для питомца (expression+pose+appeal).

**Причина.** Границы тайлов размыты → возможны странные результаты (мимика у рыбы).

**Ожидаемо.** Каждый тип животного получает уместное обогащение.

**Правка.** Сузить `cute_animal` до млекопитающих-питомцев, либо ветвить обогащение по типу животного.

**Проверка.** «рыбка» в `cute_animal` не получает неуместное обогащение.

## 7. Каталог, роутер и флоу

### 7.1 Две несовместимые архитектуры вопросов для видео

> 🟡 P1 · CONFIRMED · фронт `generate/page.tsx`, `chat.py`

**Симптом.**
- **Freeform** (скрин 1): разговорное подтверждение + звук в одном пузыре без кнопок + пилюли стиля, без нумерации.
- **Tile** (скрин 2): мастер «Question N of 4» (повод, who, text, sound), без стиля.

Звук спрашивается в обеих ветках по-разному; стиль — только в freeform; нумерация — только в tile.
Плюс в freeform два вопроса в одном пузыре без quick-reply.

**Причина.** Один и тот же параметр (звук/стиль) собирается разными способами в разных ветках.

**Ожидаемо.** Единая модель вопросов для видео (один набор полей, один UI-паттерн), независимо от входа.

**Правка.** Свести freeform и tile видео к одному набору и формату вопросов. Один вопрос = один пузырь.

**Проверка.** Freeform и tile видео используют одинаковый набор и формат вопросов.

### 7.2 `announcement` (7 тайлов) не отдаются каталогом

> 🟡 P1 · BY-DOC 🔎 · `tiles_data.py` (`get_categories`)

**Симптом.** 7 тайлов `announcement` используют image/card-конвейер, но `get_categories()` отдаёт только
image/postcard/video.

**Причина.** 7 определённых тайлов недостижимы через `/api/tiles` — скрыты намеренно или забыли выставить.

**Ожидаемо.** Каталог отдаёт ровно то, что задумано.

**Правка.** Подтвердить намерение: выставить в каталог или удалить из данных.

**Проверка.** `/api/tiles` отдаёт ожидаемый набор.

### 7.3 `type` запроса не валидируется против `tile.category`

> 🟢 P2 · BY-DOC 🔎 · `routers/generate.py`

**Симптом.** Роутер ветвится по `request.type`. Запрос `{type:"image", tile_id:"video_greeting"}` уйдёт
в image-пайплайн: `get_tile` вернёт видео-тайл (cost 2), image-билдер его не знает → fallback и списание 2 TOONTOON.

**Причина.** Нет проверки соответствия `type` и категории тайла.

**Ожидаемо.** Несоответствие → понятная ошибка, без неверного списания.

**Правка.** Валидация `type == tile.category` (или вывод `type` из тайла).

**Проверка.** Несоответствие `type`/категории → 400, TOONTOON не списаны.

## 8. Видео free-text (внутренности)

### 8.1 Free-text видео: рассинхрон полей + рудименты keyframe-эпохи

> 🟢 P2 · BY-DOC 🔎 · `video_prompts.py`

**Симптом.** `_build_freetext_storyboard` отдаёт JSON `{category, mode, loop, durationSec, anchor, motion,
audio, textOverlay, negative}`, а структура `VideoStoryboard` — `{anchor, motion, audio_enabled, audio_prompt,
negative, loop, duration, text_overlay}`.

**Причина.** camelCase↔snake_case (`durationSec`→`duration`, `textOverlay`→`text_overlay`,
`audio`→`audio_enabled`/`audio_prompt`) — место для тихих потерь полей. `mode`/`category` — рудименты
keyframe-стратегии (v2 — чистый text-to-video).

**Ожидаемо.** Все поля из LLM-JSON долетают до Seedance-payload.

**Правка.** Единый контракт имён JSON↔структуры; удалить `mode`/`category` или явно игнорировать.

**Проверка.** Нет «потерянных» полей между LLM-ответом и payload.

### 8.2 `_has_living_subject` хрупкий → вырезает живого субъекта

> 🟢 P2 · BY-DOC 🔎 · `prompt_style.py`, `gpt.py`

**Симптом.** Детект живого субъекта может промахиваться на диминутивах (котик/песик/дракончик) и
EN-множественном (`cats`, `dogs` — `strip(".,!?")` не убирает `-s`).

**Причина.** Промах → `scene_cozy` добавит `no people, no characters` → живой субъект вырезается из кадра (FIX-1).

**Ожидаемо.** Любая форма живого субъекта распознаётся как живая.

**Правка.** Двухслойный детект (леммы/корни + морфология) или вынести решение в GPT-паспорт субъекта.

**Проверка.** «котик», «два кота», «cats» → живые, `no people` не добавляется.

## 9. Отложено (видео текст-слой)

По решению продукта **текстовый слой в видео пока не трогаем**. Ниже — зафиксированные, но отложенные пункты,
чтобы не потерять контекст. Все они касаются `video_greeting` и видео-текста.

- **Видео-поздравление без людей.** `video_greeting` классифицирован как Group B «living, STYLE_3D», но билдер
  ставит якорь `STYLE_3D_SCENE_COZY` (no people) + объекты повода. Внутреннее противоречие архитектуры
  (`tiles_data.py`, `video_prompts._build_video_greeting`).
- **Опции `who` = пол, а не родство.** «Who's it for? → 👩 Woman» → текст «Happy Thanksgiving, Woman!».
  `who` должен быть адресатом (Mom/Dad/Friend), не полом.
- **Коллизия `who` и `text`.** Шаблонный «Happy Thanksgiving, {who}» против кастомного «Wishing you all the best» —
  неоднозначно, какой текст в результате.
- **Запекание текста в видео.** ffmpeg `drawtext` поверх готового MP4 — отложено.

> Когда вернёмся к видео-тексту: сначала решить «greeting с людьми или сцена-объекты», затем привести
> опции `who`/`text` и запекание текста в соответствие.
