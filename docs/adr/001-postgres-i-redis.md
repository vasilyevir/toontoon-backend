# 001. PostgreSQL как система учёта, Redis как быстрый слой

**Статус:** принято, внедрено.

## Контекст

Вся система жила в Redis: пользователи, сессии, генерации, чаты и **баланс** —
полем `teki_balance` в JSON-объекте пользователя. Журнала операций
не существовало.

Для сессий это нормально. Для денег — нет: сбой при записи молча съедает или
дарит токены, а на жалобу «я платил, куда делось» ответить нечем, потому что
истории списаний физически нет.

## Решение

Всё, что нельзя потерять, уезжает в PostgreSQL: пользователи и привязки
провайдеров, кошелёк с журналом, подписки, генерации, чаты, каталог.

Redis остаётся тем, для чего он хорош: сессии с TTL, токены ссылок, rate limit,
локи, кэш. Он перестаёт быть системой учёта — потеря Redis теперь неприятна,
но не фатальна.

Стек: SQLAlchemy 2.0 async + asyncpg + Alembic, слой репозиториев между
роутерами и таблицами.

## Следствия

Появилась зависимость, которой не было, и миграции, которых не было.
Разработка требует поднятого контейнера.

Идентификаторы остались префиксными строками (`usr_`, `gen_`), а не UUID:
так уже устроен весь код, и префикс читается в логах и ссылках.

Перечисления — обычный текст, а не native enum: списки будут расти (новая
операция генерации, новый статус подписки), а менять native enum в миграции
заметно больнее, чем текстовую колонку.

Старые данные не переносили: разработка MVP только начиналась, база заведена
чистой.
