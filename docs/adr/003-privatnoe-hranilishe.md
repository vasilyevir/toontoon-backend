# 003. Файлы в приватном хранилище, доступ через API

**Статус:** принято, внедрено.

## Контекст

Каталог `uploads/` раздавался статикой без какой-либо авторизации, и туда же
складывались референсные фотографии — то есть лица живых людей. Любой, кто
получил ссылку (а она уходит в шеринг, логи, историю браузера), открывал файл.

Плюс: файлы лежали рядом с приложением, тома в деплое не было — рестарт пода
означал потерю всех работ, при том что пользователю обещано «храним всегда».

## Решение

Объектное хранилище (MinIO в кластере, S3-совместимое API — тот же код
работает с любым провайдером). Бакет **приватный**, публичной раздачи нет.

Единственная дверь — `GET /api/media/{id}`: отдаёт свой файл или файл явно
расшаренной работы. Чужой запрос получает 404, а не 403 — существование файла
тоже информация.

Отдаём **потоком, а не редиректом** на подписанную ссылку: приложение пинит
наш сертификат, и редирект увёл бы его на хост, где пин не совпадёт.

В базе хранятся **ключи объектов, а не URL** — смена провайдера или включение
CDN не трогает ни одной строки данных.

На входе: срезается EXIF (в снимках с телефона лежат GPS-координаты съёмки),
считается хеш для дедупликации, делается миниатюра.

## Следствия

Трафик медиа идёт через приложение. Когда появится CDN, это станет редиректом —
и тогда же придётся расширить политику пиннинга на медиа-хост.

Удаление означает стирание объекта, а не только строки: это фотографии людей.

Видео пока не переехало: провайдер должен сам забрать первый кадр по ссылке,
а приватный бакет ему недоступен. Пока видео вне первой версии, вопрос
не актуален.
