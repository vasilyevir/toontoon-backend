# 13 — Платёжные системы и вебхуки

> Самая «денежная» категория. Проверяем приём платежей, обработку вебхуков платёжных провайдеров,
> создание платежей и вывод средств. Одна ошибка здесь = прямая финансовая потеря.

**Легенда:** 🔴 Critical · 🟠 High · 🟡 Medium · 🟢 Low · ⚪ Info
**OWASP:** A04/A08 · **CWE:** 345, 362, 639, 20, 840
**Принцип:** *CVSS Medium на финансовой операции = фактически High/Critical.*

## 1. Валидация вебхуков

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PAY-1.1 | Подпись вебхука проверяется | 🔴 | Нет проверки HMAC/RSA подписи → подделка платежа | HMAC-SHA256, `hmac.compare_digest` (timing-safe) |
| PAY-1.2 | `raise`, не `return` при ошибке | 🔴 | `return HttpError(...)` не прерывает обработку | `raise` — выполнение должно прерваться |
| PAY-1.3 | Секрет не в payload | 🔴 | Private key в теле вебхука → утечка при перехвате | HMAC в заголовке, не секрет в теле |
| PAY-1.4 | Проверка суммы | 🔴 | `webhook.amount ≠ purchase.amount` → оплата $1 = покупка $10000 | Строгая сверка суммы |
| PAY-1.5 | Проверка валюты | 🟠 | Оплата в другой валюте зачисляется как USD | Сверять валюту |
| PAY-1.6 | Проверка wallet/crypto | 🟠 | Mismatch только логируется, а не блокирует | Блокировать при несовпадении |
| PAY-1.7 | IP whitelisting | 🟡 | Вебхук с любого IP | Только IP провайдера |
| PAY-1.8 | HTTP-статус при ошибке | 🟡 | Невалидный вебхук → 200 (провайдер не повторит корректно) | 4xx при отказе |
| PAY-1.9 | Подпись на ВСЕ вебхуки | 🟠 | Payout/refund вебхук без подписи | Подписывать все типы |
| PAY-1.10 | Anti-replay (timestamp) | 🟠 | Повтор старого подписанного вебхука | `timestamp` + окно свежести + идемпотентность |
| PAY-1.11 | Каноникализация payload | 🟡 | Подпись по одной сериализации, тело — по другой | Документировать и сверять точную каноникализацию |

> ⚠️ **Урок из практики:** HMAC-подпись добавлялась только если задан `webhook_secret`, а payout-вебхук
> отправлялся вообще без подписи. Плюс дефолтный service-key «аутентифицировал» служебный эндпоинт
> уведомления о транзакции. Подписывай **все** вебхуки, делай `webhook_secret` обязательным.

## 2. Создание платежей

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PAY-2.1 | Цена определяется сервером | 🔴 | Клиент передаёт цену → покупка за $0.01 | Цена из БД/конфига на сервере |
| PAY-2.2 | Соответствие цены ожидаемой | 🔴 | Нет строгой сверки `user_amount == expected` | `if amount != expected: raise` |
| PAY-2.3 | Скидка вычисляется сервером | 🔴 | Клиент передаёт `discount`/`price_discount` | Скидка из БД, лимит сверху |
| PAY-2.4 | Лимиты покупок | 🟠 | `max_per_user`/`supply` только на клиенте | Серверная проверка |
| PAY-2.5 | Доступность продукта | 🟡 | `visible=True`/`status=active` только на клиенте | Серверная проверка |
| PAY-2.6 | Валюта/актив из whitelist | 🟡 | Произвольный актив | Whitelist поддерживаемых |
| PAY-2.7 | Отрицательные/нулевые суммы | 🔴 | Нет `amount > 0` | См. [06](./06-input-validation.md) §1 |

## 3. Вывод средств (Claim/Withdraw/Payout)

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PAY-3.1 | Сумма вывода = сумма earnings | 🔴 | Произвольная сумма вывода | Только агрегация подтверждённых earnings |
| PAY-3.2 | Нет эндпоинта с произвольной суммой | 🔴 | Скрытый `/private/claim-signature/` без валидаций = **бэкдор** | Удалить/строго валидировать |
| PAY-3.3 | Блокировка earnings при claim | 🟠 | Нет `select_for_update` → claim дважды | Row-lock при формировании claim |
| PAY-3.4 | Rate limiting/cooldown | 🟠 | Спам выводов | Cooldown + лимит на разовый вывод |
| PAY-3.5 | Верификация вывода (2FA/email) | 🟠 | Критичная операция без второго фактора | MFA/подтверждение |
| PAY-3.6 | Nonce из блокчейна | 🟠 | Nonce передаётся клиентом | Читать nonce из контракта |
| PAY-3.7 | Проверка знака/границ суммы | 🟠 | Admin/internal путь без проверки `amount > 0` | Централизованная валидация всех путей |
| PAY-3.8 | Списание до внешней отправки | 🟠 | `mkpayout()` до `debit()` → двойная отправка при гонке | Списать/зарезервировать до отправки, компенсация при сбое |
| PAY-3.9 | Лимиты вывода | 🟡 | Нет daily/per-tx лимита | Лимиты + алерт при превышении |
| PAY-3.10 | Audit log выводов | 🟠 | Нет записи кто/сколько/куда | Полный audit-трейл |

## 4. Идемпотентность и гонки

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PAY-4.1 | Идемпотентность зачисления | 🟠 | Повторный вебхук дублирует зачисление | Уникальный ключ (txid/ID), UNIQUE-constraint |
| PAY-4.2 | `select_for_update` на балансе | 🔴 | Чтение баланса и debit не атомарны → double-spend | `with_for_update()` на балансе и payout |
| PAY-4.3 | Atomic transaction | 🟠 | Обработка не в `transaction.atomic()` | Вся обработка в одной транзакции |
| PAY-4.4 | Status guard | 🟠 | Нет защиты от параллельного входа в обработку | Атомарный переход статуса + проверка |
| PAY-4.5 | Идемпотентный ключ на все пути | 🟠 | Merchant-payout без дедупа | `external_id`/idempotency key везде |
| PAY-4.6 | Двойное начисление | 🔴 | PENDING→PROCESSED неидемпотентно | Идемпотентная state machine |

> ⚠️ **Урок из практики:** между чтением `balance` и `debit()` нет блокировки → два параллельных `execute`
> проходят проверку и оба вызывают `mkpayout()` → реальная двойная выплата. История инцидента
> 2026-05-21 (дубль-зачисление) подтверждает: гонки в денежных путях реальны. `SELECT FOR UPDATE`
> + идемпотентность по txid (UNIQUE) обязательны.

## 5. Подтверждение платежей и reorg

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PAY-5.1 | Сумма из on-chain, не из тела | 🟠 | Сумма берётся из тела вебхука, не из блокчейна | Читать реальную сумму on-chain |
| PAY-5.2 | Верификация txid | 🔴 | Служебный вебхук о транзакции всегда success без проверки tx | Сверять txid с блокчейном (receipt) |
| PAY-5.3 | Число подтверждений | 🟠 | Слишком мало confirmations (BTC=1) | Адекватное число (BTC ≥ 2–3) |
| PAY-5.4 | Обработка reorg | 🟠 | Подтверждённый tx не откатывается при реорганизации | Мониторинг reorg + компенсация |
| PAY-5.5 | Двойная трата плательщика | 🟠 | Приём при малом числе подтверждений | Увеличить confirmations для крупных сумм |

> ⚠️ **Урок из практики:** инъекция фейковых платежей через служебный вебхук уведомления (для части
> сетей всегда возвращался success без верификации txid) — Critical. Перед зачислением **верифицируй
> транзакцию в блокчейне**.

## 6. Курсы и конвертация

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PAY-6.1 | Источник курса надёжен | 🟠 | Один источник, без санити-границ | Медиана нескольких, отклонение > X% → алерт |

| PAY-6.5 | Округление в пользу системы | 🟢 | Ошибки округления накапливаются | Явные правила округления |

## Быстрые команды проверки

```bash
# Подпись вебхуков
rg -i "hmac|compare_digest|verify.*signature|X-.*Signature|webhook_secret" --type py
rg "return.*Http(Error|Response)" --type py    # return вместо raise в проверках

# Сверка суммы
rg -i "amount|price" -A3 | rg -i "webhook|payload|request" | rg -v "=="

# Гонки/атомарность в выплатах
rg -i "with_for_update|select_for_update|\.debit\(|\.credit\(|mkpayout|payout" --type py
rg "transaction\.atomic|db\.session\.commit" --type py

# Клиент задаёт цену
rg -i "request\.(data|POST|json).*\b(amount|price|discount|total)\b" --type py

# Скрытые/бэкдор эндпоинты подписи
rg -i "include_in_schema\s*=\s*False|/private/|/internal/|claim.?signature" 
```
