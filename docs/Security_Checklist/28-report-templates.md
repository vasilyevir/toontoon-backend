# 28 — Шаблоны отчётов

> Единые шаблоны для оформления находок, сводных таблиц и итогового отчёта. Консистентность отчётов
> ускоряет ревью и приоритизацию фиксов.

**Легенда:** 🔴 Critical · 🟠 High · 🟡 Medium · 🟢 Low · ⚪ Info

---

## 1. Шаблон отдельной находки

Каждую находку оформляй строго по этому шаблону:

```markdown
### [SEVERITY] Краткое название

**ID:** PROJ-CAT-001
**Файл:** `path/to/file.py:line`
**Проект/компонент:** backend / frontend / infra
**Категория:** Auth / Payment / Signature / Admin / Config / XSS / Infra / SSRF / ...
**OWASP / CWE:** A01:2021 / CWE-639
**CVSS:** 3.1 /AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N (≈ 8.6)
**Статус:** Open / Mitigated / Fixed / Won't fix
**Риск поломки фикса:** Низкий / Средний / 🟥 Высокий (деньги)

**Описание:**
Что именно обнаружено, какой код задействован.

**Вектор атаки:**
1. Шаг 1
2. Шаг 2
3. Шаг 3

**Последствия:**
- Финансовые: [да/нет] — какие именно
- Данные: [да/нет] — что утекает
- Доступность: [да/нет] — DoS/downtime

**Уязвимый код:**
​```python
# vulnerable code here
​```

**Как безопасно проверить (неразрушающе):**
Статически / динамически на staging — конкретная команда.

**Рекомендация:**
Как исправить, с примером кода.

**План отката:**
Как откатить фикс, если что-то сломается.

**Трудозатраты:** S / M / L

**Связанные находки:** #X, #Y (если усиливают друг друга в цепочку)
```

## 4. Executive Summary (для руководства)

```markdown
# Executive Summary

**Система:** <название, тип>
**Дата:** YYYY-MM-DD
**Аудитор:** <имя/команда>
**Тип работ:** неразрушающий аудит / пентест
**Общий уровень риска:** 🔴 Critical / 🟠 High / 🟡 Medium

## TL;DR (3–5 предложений без жаргона)
- Главный вывод одним предложением.
- Что именно под угрозой (деньги/данные/доступность).
- Корневая причина большинства критичных находок.

## Топ-5 проблем (чинить в первую очередь)
| # | ID | Проблема | Серьёзность | Статус |
|---|----|----------|-------------|--------|
| 1 | ... | ... | 🔴 | Open |

## Сильные стороны (что уже сделано хорошо)
- ... (честная картина повышает доверие к отчёту)

## Что сделано и что дальше
- Выполнено: ...
- В работе: ...
- Очередь: ...
```

**Sign-off:** <аудитор>, дата

**Заметки:** ...
```

## 6. Матрица приоритизации

```markdown
Priority = Severity × Exploitability × Business Impact

| Находка | Severity | Exploitability | Business Impact | Priority | Порядок |
|---------|----------|----------------|-----------------|----------|---------|
| PROJ-001 | 5 | 5 | 5 | 125 | 1 |
| PROJ-003 | 4 | 3 | 4 | 48 | 2 |
```

*При равной критичности — сначала то, что ближе к деньгам/ключам/PII.*

---

## 7. Рекомендации по стилю отчёта

| # | Рекомендация |
|---|--------------|
| REP-1 | Честная картина: указывай и сильные стороны, не только проблемы |
| REP-2 | Каждая находка — с конкретным файлом:строкой и вектором |
| REP-3 | Рекомендация — с примером кода и планом отката |
| REP-4 | Помечай 🟥 всё, что затрагивает деньги/ключи (maintenance-окно) |
| REP-5 | Связывай находки в цепочки (Medium+Medium может = Critical) |
| REP-6 | Разделяй «в скоупе» и «вне скоупа» (передавай чужое ответственным) |
| REP-7 | Не публикуй реальные значения секретов/ключей в отчёте (redact) |
| REP-8 | Указывай CVSS + бизнес-контекст (Medium на деньгах = High) |
```
