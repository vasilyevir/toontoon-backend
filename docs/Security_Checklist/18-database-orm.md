## 1. Гонки и атомарность

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| DB-1.1 | `select_for_update` на финансах | 🔴 | Покупки/earnings/nonce/баланс без row-lock | `select_for_update()` на критичных |
| DB-1.2 | Atomic transactions | 🟠 | Финансовые операции вне `transaction.atomic()` | Обернуть в атомарную транзакцию |
| DB-1.3 | Атомарные инкременты | 🟠 | Read-modify-write вместо `F()`/`UPDATE ... SET x=x+?` | Атомарные выражения БД |
| DB-1.4 | Изоляция транзакций | 🟡 | Слишком слабый isolation level для инвариантов | Подобрать уровень (SERIALIZABLE где нужно) |
| DB-1.5 | Идемпотентность операций | 🟠 | Повтор дублирует записи | UNIQUE + `get_or_create` |
| DB-1.6 | Поддержка FOR UPDATE в СУБД | 🟡 | SQLite игнорирует FOR UPDATE | Учитывать особенности СУБД / PostgreSQL |

## 2. Привилегии и доступ

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| DB-2.1 | Least privilege для app-юзера | 🟠 | App использует root/postgres/`ALL PRIVILEGES` | Отдельный юзер, минимальные гранты |
| DB-2.2 | Root ≠ app пароль | 🟠 | Один пароль на root и app | Разные сильные пароли |
| DB-2.3 | Host-маска пользователя | 🟡 | `'user'@'%'` (любой хост) | Сузить до подсети |
| DB-2.4 | БД не публична | 🟠 | Порт 3306/5432/27017 на `0.0.0.0` | Только внутренняя сеть |
| DB-2.5 | Дефолтные креды | 🔴 | `postgres/postgres`, `root/rootpassword` | Сильные уникальные |
| DB-2.6 | Web не имеет root к БД | 🟠 | Web-процесс с root-доступом к БД с ключами | Узкие гранты на нужные таблицы |
| DB-2.7 | Credentials из env | 🟠 | Захардкоженные DB-креды | Только env/vault |

> ⚠️ **Урок из практики:** `DB_ROOT_PASSWORD == DB_APP_PASSWORD`, а web-процесс получал root-доступ к
> БД, где лежат приватные ключи. Плюс `'app_user'@'%'` с `ALL PRIVILEGES`. Разделяй root и app,
> минимизируй гранты, сужай host-маску.

## 3. Целостность данных

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| DB-3.1 | Soft delete для финансов | 🟡 | Hard delete финансовых записей | Soft delete, не удалять hard |
| DB-3.2 | DB-constraints на суммы | 🟠 | Нет `CHECK amount >= 0` | Constraint + `MinValueValidator` |
| DB-3.3 | Валидаторы на модели | 🟠 | Валидация только в форме/сервисе | Модель-уровень (защита от direct write) |
| DB-3.4 | Уникальность инвариантов | 🟠 | Нет UNIQUE где нужен | UniqueConstraint |
| DB-3.5 | Foreign key целостность | 🟡 | Осиротевшие записи | FK + on_delete стратегия |
| DB-3.6 | Unmanaged models drift | 🟢 | Вторичная БД без миграций → дрифт схемы | Контроль схемы |

## 4. Миграции

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| DB-4.1 | Нет user input в миграциях | 🟡 | `RunSQL`/`RunPython` с внешними данными | Ревью, без user-controlled |
| DB-4.2 | Миграции ревьюятся | 🟢 | Автогенерация без проверки | Обязательный review |
| DB-4.3 | Обратимость | 🟢 | Нет отката для рискованных миграций | Reverse-миграции |
| DB-4.4 | Безопасность данных при миграции | 🟡 | Утечка/потеря при data-миграции | Бэкап до, проверка после |

## 5. Бэкапы

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| DB-5.1 | Шифрование бэкапов | 🟠 | Plaintext-дамп с ключами/PII | Шифровать (age/gpg/SSE) |
| DB-5.2 | Offsite-копия | 🟡 | Только локальные бэкапы | Offsite (S3 с SSE/immutability) |
| DB-5.3 | Тест восстановления | 🟡 | Restore не проверялся | Регулярный тест restore |
| DB-5.4 | Права на файлы бэкапов | 🟡 | Читаемы всеми | `600`, отдельный владелец |
| DB-5.5 | Периодичность/RPO | 🟢 | Неизвестна частота | Определить RPO/RTO |
| DB-5.6 | PII masking для dev/staging | 🟡 | Прод-данные в staging без анонимизации | Маскирование email/кошельков/имён |

## 6. Производительность как DoS

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| DB-6.1 | Query timeout | 🟡 | Нет `statement_timeout` → тяжёлый запрос блокирует пул | Настроить таймаут |
| DB-6.2 | Connection pooling | 🟡 | Нет лимита соединений → исчерпание | Лимит + timeout |
| DB-6.3 | N+1 запросы | 🟢 | Нет `select_related`/`prefetch_related` | Оптимизация выборок |
| DB-6.4 | Индексы на фильтруемых полях | 🟢 | Full scan на больших таблицах | Индексы |
| DB-6.5 | Пагинация тяжёлых выборок | 🟡 | Дамп всей таблицы (см. [09](./09-api-security.md)) | Серверная пагинация |

## Быстрые команды проверки

```bash
# Гонки/атомарность
rg "select_for_update|with_for_update|transaction\.atomic|F\(" --type py
rg "\.save\(\)" -l --type py | xargs rg -L "transaction\.atomic"    # save без atomic

# Привилегии/доступ
rg -i "GRANT ALL|ALL PRIVILEGES|'%'|root|postgres" -g "*.sql" -g "*.yml"
rg -i "MARIADB_ROOT|POSTGRES_PASSWORD|DB_PASSWORD|DATABASE_URL"

# Публикация портов БД
rg -i "3306|5432|27017|6379" -g "docker-compose*.yml"

# Constraints/валидаторы
rg -i "MinValueValidator|CheckConstraint|UniqueConstraint|constraints\s*=" --type py

# Миграции
rg -i "RunSQL|RunPython" --type py
```
