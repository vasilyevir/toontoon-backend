# 22 — Логирование, мониторинг и наблюдаемость

> Логи — источник обнаружения атак и forensics, но также источник утечек. Проверяем: что логируется,
> не утекают ли секреты, есть ли алертинг на аномалии, защищены ли логи, синхронизировано ли время.

**Легенда:** 🔴 Critical · 🟠 High · 🟡 Medium · 🟢 Low · ⚪ Info
**OWASP:** A09:2021 (Security Logging & Monitoring Failures) · **CWE:** 532, 778, 223, 117

## 1. Утечки в логи

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| LOG-1.1 | Секреты не в логах | 🟠 | Полный API-ключ/токен/пароль в логах | Redaction-утилита, маскирование |
| LOG-1.2 | Пароли на login/register | 🟠 | Логирование `request.body` целиком | Исключить пароли |
| LOG-1.3 | Приватные ключи | 🔴 | Ключи/сиды в логах | Запрет логирования ключей |
| LOG-1.4 | PII в логах | 🟠 | Email/кошельки/телефоны в открытых логах | Маскирование PII |
| LOG-1.5 | Payload целиком | 🟡 | Тела запросов/ответов с чувствительным | Логировать выборочно |
| LOG-1.6 | Консистентность маскирования | 🟡 | В одном месте маскируется, в другом нет | Единая утилита логирования |
| LOG-1.7 | Sentry/APM scrubbing | 🟠 | Секреты уходят во внешний мониторинг | `before_send`/scrubbing |
| LOG-1.8 | Log injection | 🟡 | `\r\n` в user input → подделка строк лога | Sanitize перед логированием |

> ⚠️ **Урок из практики:** функция отправки уведомления логировала **полный** API-ключ мерчанта на WARNING,
> тогда как соседняя функция маскировала до `apikey[:8]`. Непоследовательность = утечка. Единая
> redaction-утилита для всех логов.

## 2. Полнота аудита

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| LOG-2.1 | Аудит критичных действий | 🟠 | Нет записи логина/выплат/смены прав | Логировать security-события |
| LOG-2.2 | Create/update/delete | 🟡 | Аудит логирует только change, не create/delete | Логировать все операции |
| LOG-2.3 | Before/after значения | 🟡 | Нет старого/нового значения | Фиксировать diff |
| LOG-2.4 | Кто/когда/откуда | 🟡 | Нет user/IP/timestamp | Полный контекст |
| LOG-2.5 | Неудачные попытки | 🟡 | Failed auth не логируются | Логировать отказы |
| LOG-2.6 | Аудит подписей/выплат | 🟠 | Нет записи генераций подписей | Логировать wallet/amount/ts |
| LOG-2.7 | Сбой аудита не глушится | 🟢 | `except: pass` вокруг аудита | Реагировать/алертить |

## 3. Алертинг на аномалии

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| LOG-3.1 | Денежные аномалии | 🟠 | Массовый claim/выплата без алерта | Алерты на всплески |
| LOG-3.2 | Auth failures spike | 🟡 | Всплеск неудачных логинов | Алерт (brute-force/атака) |
| LOG-3.3 | 4xx/5xx spike | 🟡 | Всплеск ошибок без реакции | Алерт (атака/деградация) |
| LOG-3.4 | «Wrong key»/отказы auth | 🟡 | Служебные отказы не мониторятся | Алерт на подбор ключей |
| LOG-3.5 | Error rate monitoring | 🟡 | Нет мониторинга ошибок | Алерт на рост 5xx |
| LOG-3.6 | AML/fraud флаги | 🟡 | FLAGGED без уведомления | Алерт на подозрительное |

## 4. Защита и хранение логов

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| LOG-4.1 | Централизация логов | 🟡 | Логи только локально | ELK/Loki/централизованный сбор |
| LOG-4.2 | Иммутабельность | 🟡 | Логи можно подделать/удалить | Immutable storage / WORM |
| LOG-4.3 | Ротация | 🟢 | Docker json-file без лимита → диск | `max-size`/`max-file` |
| LOG-4.4 | NTP sync | 🟢 | Рассинхрон времени (forensics/TOTP) | Синхронизация времени |
| LOG-4.5 | Retention policy | 🟢 | Логи хранятся вечно/слишком мало | Политика хранения |
| LOG-4.6 | Доступ к логам ограничен | 🟡 | Логи с секретами доступны широко | RBAC на логи |

> 💡 **Forensics-ценность:** качественные логи (auditd/journald/access-логи прокси) позволяют по факту
> инцидента доказать, был ли доступ к инфраструктуре. В одном из разборов именно логи подтвердили, что хост
> не был скомпрометирован (все SSH-входы — по ключу владельца). Логи — не только защита, но и алиби.

## Быстрые команды проверки

```bash
# Что логируется
rg -i "logger\.(info|warning|debug|error)\(|console\.log\(|print\(" | rg -i "key|token|password|secret|apikey"

# Redaction
rg -i "redact|mask|sanitize.*log|before_send|scrub" 

# Реальная утечка в логах контейнера
docker logs --tail 500 <container> 2>&1 | rg -i "api.?key|password|secret|priv"

# Ротация Docker-логов
docker info | grep -i logging
rg -i "max-size|max-file|logging" -g "docker-compose*.yml"

# NTP
timedatectl
```
