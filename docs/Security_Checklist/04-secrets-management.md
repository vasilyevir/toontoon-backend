# 04 — Управление секретами

> Секреты (ключи, пароли, токены) — самая частая причина полной компрометации. Проверяем: где
> хранятся, как попадают в код/логи/git, дефолты, ротацию. Один утёкший ключ = вся система.

**Легенда:** 🔴 Critical · 🟠 High · 🟡 Medium · 🟢 Low · ⚪ Info
**OWASP:** A02:2021 (Cryptographic Failures) / A05 · **CWE:** 798, 312, 321, 522, 1188, 260

## 1. Секреты в коде и git-истории

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SEC-1.1 | `.env` в `.gitignore` | 🔴 | `.env`, `.env.*`, `**/.env` не игнорируются | Добавить все варианты в `.gitignore` |
| SEC-1.2 | Нет `.env` в git-истории | 🔴 | `git log --all --diff-filter=A -- '*.env*'` | Purge истории (BFG/filter-repo) + ротация |
| SEC-1.3 | Нет hex-ключей в коде | 🔴 | `0x[0-9a-f]{40,}`, приватные ключи в исходниках | Только из env/vault |
| SEC-1.4 | Нет API-ключей в коде | 🔴 | `sk_`, `pk_`, `AKIA`, `ghp_`, токены провайдеров | Вынести в секрет-хранилище |
| SEC-1.5 | Секреты в конфигах/yaml | 🟠 | Пароли в `values.yaml`/`ConfigMap` открытым текстом | Vault/Secrets, не ConfigMap |
| SEC-1.6 | Токены в URL провайдеров | 🟠 | RPC `https://.../TOKEN`, `user:pass@host` в URL | Вынести креды из URL |
| SEC-1.7 | Pre-commit secret scanning | 🟡 | Нет хука gitleaks/detect-secrets | Настроить pre-commit hook |

> ⚠️ **Урок из практики:** `.env` был корректно вне git — это правильно. Но на диске имел права `-rw-rw-r--`
> (читаемый всеми пользователями хоста) и содержал живые токены внешних RPC-провайдеров и API. `.gitignore` — не всё.

## 2. Дефолтные и переиспользуемые секреты

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SEC-2.1 | Нет дефолтных секретов | 🔴 | `= "dev"`, `"changeme"`, `"admin"`, `"test"` как fallback | Fail-closed: нет env → не стартовать |
| SEC-2.2 | Один пароль на всё | 🔴 | Один пароль на admin/БД/метрики/адаптеры | Уникальный секрет на каждый сервис |
| SEC-2.3 | `.env.example` без реальных значений | 🟠 | Реальные секреты в примере | Только плейсхолдеры (`key`, `secret`) |
| SEC-2.4 | Дефолтные креды в compose | 🔴 | `${VAR:-changeme}`, `rootpassword` | Убрать опасные дефолты |
| SEC-2.5 | Разные ключи для разных функций | 🟡 | Один ключ для purchase/referral/royalty подписей | Отдельный ключ на каждую функцию |
| SEC-2.6 | Дефолтные креды провайдеров/БД | 🔴 | `postgres/postgres`, `admin/admin` | Сильные уникальные пароли |

> ⚠️ **Типичный корень критичности = один дефолтный backend-key** (переменная не задана → активен
> дефолт). Плюс один общий пароль на admin/БД/метрики/шифрование кошельков. Дефолтный секрет =
> отсутствие секрета.

## 3. Хранение секретов (env / vault / KMS)

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SEC-3.1 | Secrets через vault/KMS | 🟠 | Секреты в plaintext-файле рядом с кодом | HashiCorp Vault / cloud KMS / Docker secrets |
| SEC-3.2 | Права на файлы секретов | 🟠 | `.env` читаем группой/всеми (`-rw-rw-r--`) | `chmod 600 .env`, каталог `700`, владелец — сервис |
| SEC-3.3 | Секреты не в CI/CD логах | 🟠 | `--build-arg SECRET=...` → в layer history | Secrets через защищённые CI-переменные/mounts |
| SEC-3.4 | Секреты не в образе | 🟠 | `ENV SECRET=...` / скопированный `.env` в образ | Runtime-инъекция, не build-time |
| SEC-3.5 | Отдельные секреты на среды | 🟡 | Один секрет на stage/prod | Разные значения per-env |
| SEC-3.6 | Шифрование секретов at-rest | 🟠 | БД/бэкапы с секретами не шифрованы | Шифрование, см. [14](./14-cryptography-signatures.md) |

## 4. Секреты в логах и ответах

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SEC-4.1 | Ключи не логируются | 🟠 | `logger.info(f"...{api_key}...")`, полный apikey в WARNING | Redaction-утилита, маскировать (`key[:6]+"…"`) |
| SEC-4.2 | Payload не логируется целиком | 🟡 | Тело запроса/выплаты в логах | Логировать только нужное, без секретов |
| SEC-4.3 | Секреты не в ответах API | 🔴 | Эндпоинт возвращает ключ/секрет в JSON | Никогда не возвращать секреты клиенту |
| SEC-4.4 | Секреты не в error/stack trace | 🟠 | Секрет в тексте исключения | Generic-ошибка, детали в лог |
| SEC-4.5 | Sentry/APM без секретов | 🟠 | Секреты уходят в внешний мониторинг | `before_send` hook / scrubbing |

> ⚠️ **Урок из практики:** служебный эндпоинт возвращал ключ шифрования кошельков **в теле ответа** — Critical.
> Плюс полный API-ключ мерчанта логировался на уровне WARNING. Секреты не в ответах и не в логах.

## 5. Ротация и управление жизненным циклом

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SEC-5.1 | Процедура ротации | 🟡 | Нет плана ротации ключей | Регламент ротации + автоматизация |
| SEC-5.2 | Ротация после утечки | 🟠 | Утёкшие секреты не отозваны | Считать скомпрометированными, перевыпустить |

| SEC-5.5 | Break-glass / офлайн-резерв | 🟡 | Потеря ключа = потеря доступа к средствам | Офлайн-резерв критичных ключей |

## 6. Секреты на фронтенде

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SEC-6.1 | Write-токены не в `NEXT_PUBLIC_` | 🔴 | Write-токен CMS/API в `NEXT_PUBLIC_` → в бандле | Только read-токены в публичных переменных |
| SEC-6.2 | Нет захардкоженных ключей | 🟠 | Fallback с реальным API-ключом в JS | Только через env, без реальных дефолтов |

## Быстрые команды проверки

```bash
# .env когда-либо коммитился
git log --all --diff-filter=A --name-only -- '*.env*'
git log --all -p -G "0x[0-9a-fA-F]{40,}" -- '*.py' '*.env*' '*.yaml'

# Секреты в текущем коде
rg "(sk_|pk_|AKIA|ghp_|xox[baprs]-|AIza)[0-9A-Za-z_\-]{10,}"
rg -i "(password|secret|token|api_key|private_key)\s*[:=]\s*['\"][^'\"]{6,}"
rg "0x[0-9a-fA-F]{40,}"

# Дефолтные секреты
rg -i "['\"](dev|changeme|password123|admin|rootpassword|secret|test)['\"]"

# Права на .env
stat -c '%A %U:%G' .env 2>/dev/null

# Автоинструменты
gitleaks detect --source . --no-banner
trufflehog git file://. --only-verified
```
