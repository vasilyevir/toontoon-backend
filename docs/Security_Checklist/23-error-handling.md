# 23 — Обработка ошибок и Information Disclosure

> Ошибки и их сообщения не должны раскрывать внутреннее устройство системы. Проверяем stack trace,
> различие 403/404, verbose-заголовки, graceful degradation.

**Легенда:** 🔴 Critical · 🟠 High · 🟡 Medium · 🟢 Low · ⚪ Info

## 1. Stack trace и debug

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| ERR-1.1 | Stack trace не клиенту | 🟠 | `traceback.format_exc()` в JSON-ответе | Generic-ошибка клиенту, детали в лог |
| ERR-1.2 | `DEBUG=False` в проде | 🟠 | `DEBUG=True` → полный traceback + settings | Отключить debug в проде |
| ERR-1.3 | Dev-режим выключен | 🟡 | `DEV_MODE`, `/console` (Werkzeug), Flask debugger | Отключить в проде |
| ERR-1.4 | Кастомные error handlers | 🟡 | Дефолтные страницы ошибок с деталями | 400/403/404/500 → generic |
| ERR-1.5 | Секреты в ошибках | 🟠 | Секрет в тексте исключения | Не включать секреты |

> ⚠️ **Урок из практики:** служебные эндпоинты возвращали клиенту `traceback.format_exc()` в JSON —
> раскрытие путей, модулей, версий, внутренних имён. Клиенту — `{"error":"internal"}`, 500;
> `app.logger.exception(...)` — в лог.

## 2. Сообщения об ошибках

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| ERR-2.1 | БД-ошибки обёрнуты | 🟠 | `IntegrityError`/`OperationalError` с именами таблиц | Generic-сообщение |
| ERR-2.2 | 403 vs 404 | 🟡 | 403 подтверждает существование объекта | 404 на чужие ресурсы |
| ERR-2.3 | User enumeration через ошибки | 🟡 | Разные сообщения для существующих/нет | Единообразный ответ (см. [01](./01-authentication.md)) |
| ERR-2.4 | Verbose validation errors | 🟢 | Раскрытие внутренней структуры валидации | Разумная детализация |
| ERR-2.5 | Timing как раскрытие | 🟡 | Разное время ответа выдаёт состояние | Единообразное время |

## 3. Раскрытие через метаданные

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| ERR-3.1 | `Server`/`X-Powered-By` | 🟡 | Раскрытие стека/версий | Удалить/замаскировать |
| ERR-3.2 | Version banners | 🟡 | Версии в заголовках/ответах | Скрыть |
| ERR-3.3 | Комментарии в HTML/JS | 🟢 | Внутренняя инфа в комментариях | Чистка при сборке |
| ERR-3.4 | Debug-эндпоинты | 🟡 | `/debug`, `/actuator`, `/__debug__` | Закрыть/удалить |
| ERR-3.5 | Directory listing | 🟡 | Открытый листинг директорий | Отключить |
| ERR-3.6 | `.git`/`.env`/backup доступны | 🟠 | `/.git/HEAD`, `/.env`, `/*.bak` по URL | Блок на веб-сервере |

## 4. Graceful degradation

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| ERR-4.1 | Fallback внешних сервисов | 🟡 | 500 с деталями при недоступности провайдера | Graceful fallback |
| ERR-4.2 | Fail-safe vs fail-open | 🟠 | При ошибке проверки — пропуск (fail-open) | Fail-closed на безопасности |
| ERR-4.3 | Таймауты внешних вызовов | 🟡 | Зависание при недоступном сервисе | Таймауты + circuit breaker |
| ERR-4.4 | Идемпотентность при retry | 🟡 | Повтор после ошибки дублирует | Идемпотентные операции |

## Быстрые команды проверки

```bash
rg -i "traceback|format_exc|DEBUG\s*=\s*True|DEV_MODE|debug\s*=\s*True" 
rg -i "except.*:\s*$" -A2 | rg -i "return.*str\(e\)|return.*exception"
rg -i "X-Powered-By|Server:|version" 

# Живая проверка
curl -sI https://target/ | grep -iE "server|x-powered-by"
curl -s https://target/.git/HEAD https://target/.env    # должно быть 404/403
```
