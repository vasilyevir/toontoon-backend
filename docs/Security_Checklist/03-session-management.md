# 03 — Управление сессиями и токенами

> Как хранятся, передаются и инвалидируются идентификаторы сессии/токены — на сервере и на клиенте.
> Ошибки здесь превращают XSS/CSRF в полный захват аккаунта.

**Легенда:** 🔴 Critical · 🟠 High · 🟡 Medium · 🟢 Low · ⚪ Info
**OWASP:** A07:2021 · **ASVS:** V3 · **CWE:** 384 (Session Fixation), 613, 614, 522

## 1. Cookie-флаги и хранение на клиенте

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SESS-1.1 | `HttpOnly` | 🔴 | Токен-cookie без `HttpOnly` → XSS крадёт | `HttpOnly` на все auth-cookie |
| SESS-1.2 | `Secure` | 🟠 | Без `Secure` → cookie по HTTP | `Secure` в проде (HTTPS-only) |
| SESS-1.3 | `SameSite` | 🟠 | Нет `SameSite` → CSRF | `Strict` или `Lax` |
| SESS-1.4 | Токены не в `localStorage` | 🟠 | `localStorage`/`sessionStorage` доступны из JS → XSS | HttpOnly-cookie для токенов |
| SESS-1.5 | `Domain`/`Path` scope | 🟡 | Слишком широкий `Domain` (общий eTLD+1 для поддоменов) | Минимальный scope; `__Host-` префикс |
| SESS-1.6 | Подпись cookie | 🟠 | Незашифрованные/неподписанные session-cookie | Подпись сильным `SECRET_KEY` |
| SESS-1.7 | Токены не в URL | 🟠 | Session/token в query string → логи, Referer | Только cookie/заголовок |

## 2. Жизненный цикл сессии

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SESS-2.1 | Session fixation | 🟠 | ID сессии не меняется после логина | Регенерировать session ID при аутентификации |
| SESS-2.2 | Инвалидация при logout | 🟠 | Сессия остаётся валидной на сервере | Удалять серверную запись сессии |
| SESS-2.3 | Idle timeout | 🟡 | Сессия живёт бесконечно без активности | Таймаут неактивности (напр. 30 мин) |
| SESS-2.4 | Absolute timeout | 🟡 | Нет абсолютного лимита жизни | Max lifetime (напр. 12–24 ч) |
| SESS-2.5 | Отзыв при смене пароля | 🟠 | Старые сессии живут после смены | Инвалидация всех сессий |
| SESS-2.6 | Concurrent sessions | 🟡 | Неограниченное число сессий | Лимит / список активных с возможностью отзыва |
| SESS-2.7 | Ротация при privilege change | 🟡 | Повышение прав в старой сессии | Регенерация при смене роли |

## 3. Серверное хранилище сессий

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SESS-3.1 | Session store защищён | 🟠 | Redis без пароля хранит сессии → захват admin-сессии | `requirepass` + сеть/TLS |
| SESS-3.2 | Энтропия session ID | 🟠 | Предсказуемый/короткий ID | CSPRNG, ≥ 128 бит |
| SESS-3.3 | Отзыв на стороне сервера | 🟡 | Нельзя принудительно завершить сессию | Механизм revoke по user/session |
| SESS-3.4 | Шифрование чувствительного в сессии | 🟡 | PII/токены в открытой сессии | Минимум данных, шифрование |

> ⚠️ **Урок из практики:** Redis без `requirepass` хранил сессии → при доступе к Redis (в т.ч. через SSRF)
> возможен захват admin-сессии. Session store — часть attack surface.

## 4. Токены на фронтенде (SPA)

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| SESS-4.1 | Хранение токенов | 🟠 | `js-cookie` без HttpOnly / localStorage | HttpOnly-cookie, выставляемая сервером |
| SESS-4.2 | Полная очистка при logout | 🟡 | Удаляется только access, refresh остаётся | Чистить оба токена + query cache |
| SESS-4.3 | 401-обработка | 🟡 | При 401 не очищаются все токены → stale state | Очистка всех токенов и редирект на login |
| SESS-4.4 | Token refresh flow | 🟡 | Нет авто-обновления / гонки при refresh | Единый refresh с мьютексом/очередью |
| SESS-4.5 | Токен не логируется | 🟢 | `console.log(token)` | Убрать логирование токенов |

## Быстрые команды проверки

```bash
# Cookie без флагов безопасности
rg -i "set_cookie|SESSION_COOKIE|CSRF_COOKIE" --type py
rg -i "httponly|secure|samesite" --type py

# Токены в localStorage (frontend)
rg "localStorage\.(set|get)Item\(.*(token|jwt|access|refresh|auth)" 
rg "sessionStorage\.(set|get)Item" 

# Session fixation: регенерация после логина
rg -A5 "login|authenticate" --type py | rg -i "cycle_key|regenerate|session.*regenerat"

# Redis без пароля
rg -i "redis.*requirepass|SESSION_REDIS" 
```
