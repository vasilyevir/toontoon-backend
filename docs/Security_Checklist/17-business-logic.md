# 17 — Бизнес-логика

> Уязвимости логики приложения, которые не ловят сканеры: обход рабочих процессов, гонки, TOCTOU,
> манипуляция скидками/промо, злоупотребление бизнес-потоками. Требуют понимания домена.

| # | Проверка | Крит. | Что искать / вектор | Как исправить |

| BIZ-1.1 | State machine bypass | 🟠 | PENDING→COMPLETED минуя PROCESSING | Явные разрешённые переходы |

## 2. Гонки и TOCTOU

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| BIZ-2.1 | TOCTOU | 🟠 | Проверка прав/условия в начале, запись позже | Проверка+запись в одной транзакции с lock |
| BIZ-2.2 | Race на балансе/лимитах | 🔴 | Параллельные запросы обходят лимит/баланс | `select_for_update` + atomic |

| BIZ-2.5 | Гонка на счётчиках/supply | 🟠 | Превышение supply при параллелизме | Атомарный декремент/lock |

## 5. Административные операции

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| BIZ-5.1 | Audit log действий | 🟠 | Нет записи кто/что/когда (before/after) | Полный audit-трейл |

| BIZ-5.7 | Аудит не глушит ошибки | 🟢 | Сбой аудита молча проглатывается → save проходит | Реагировать на сбой аудита |

## Быстрые команды проверки

```bash
# State/статусы
rg -i "status\s*=|STATUS_|state\s*=|PENDING|COMPLETED|PROCESSING" --type py
rg -i "transition|state_machine|FSM|workflow" --type py

# Гонки
rg -i "select_for_update|with_for_update|transaction\.atomic|F\(" --type py

# Промо/скидки
rg -i "discount|promo|coupon|voucher|referral" --type py | rg -i "request|client"

# Idempotency
rg -i "idempot|external_id|unique_together|get_or_create" --type py

# Audit
rg -i "audit|log_action|save_model|before.*after" --type py
```

> 💡 Бизнес-логику плохо ловят автосканеры — читай код доменных сервисов и задавай вопрос «что если
> сделать это дважды / параллельно / в другом порядке / с граничным значением?».
