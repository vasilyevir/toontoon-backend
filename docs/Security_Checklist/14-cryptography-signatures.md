# 14 — Криптография и серверные подписи

> Правильное использование криптографии: серверные ECDSA-подписи для смарт-контрактов, шифрование
> данных at-rest, KDF, генерация случайности, защита от replay. Ошибки крипто = кража средств и утечка.

## 1. Хранение приватных ключей

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| CRY-1.1 | Ключ только из env/vault | 🔴 | Hex-ключи в коде | `env.str("SIGNER_KEY")` / KMS |
| CRY-1.2 | Ключ не в git-истории | 🔴 | `git log -p -S "0x[0-9a-f]{64}"` | Purge + ротация |
| CRY-1.3 | Ключ не логируется | 🟠 | `logger.info(f"...{key}...")` | Запрет логирования ключей |
| CRY-1.4 | Ключ не в ответах API | 🔴 | Эндпоинт возвращает ключ | Никогда не отдавать ключ |
| CRY-1.5 | Разные ключи для функций | 🟡 | Один ключ на purchase/referral/royalty | Отдельный ключ на функцию |
| CRY-1.6 | Hot wallet изоляция | 🟠 | Горячий ключ на том же хосте, что и web | Изоляция подписывающего сервиса/HSM |
| CRY-1.7 | Ключи в бэкапах шифрованы | 🟠 | Дамп БД с ключами в открытом виде | Шифрование бэкапов |

## 2. Серверные подписи (ECDSA)

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| CRY-2.1 | Подпись содержит user address | 🔴 | Без адреса → cross-user replay | Включить адрес в подпись |
| CRY-2.2 | Подпись содержит contract address | 🟠 | Без контракта → cross-contract replay | Включить адрес контракта |
| CRY-2.3 | Подпись содержит nonce | 🔴 | Без nonce → replay старой подписи | Включить nonce |
| CRY-2.4 | Nonce из on-chain | 🟠 | Nonce из БД/клиента | Читать nonce из контракта |
| CRY-2.5 | Chain ID в подписи | 🟠 | Cross-chain replay (mainnet↔testnet) | EIP-712 domain separator с `chainId` |
| CRY-2.6 | Deadline/expiry | 🟠 | Подпись живёт вечно | `deadline`, проверка в контракте |
| CRY-2.7 | Параметры от сервера | 🔴 | Сумма/pack_id/round_id из запроса клиента | Из БД, не из запроса |
| CRY-2.8 | Формат совпадает с контрактом | 🟠 | Типы/порядок `abi.encodePacked` не совпадают | Точная сверка с контрактом |
| CRY-2.9 | Signature malleability | 🟡 | `s` не в нижней половине кривой (EIP-2) | Каноническая подпись |
| CRY-2.10 | EIP-712 typed data | 🟡 | Слепая подпись хэша | Структурированная EIP-712 подпись |

## 4. Шифрование данных at-rest

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| CRY-4.1 | Шифрование включено | 🔴 | Шифрование отключено/дефолтный пароль | Включить с сильным ключом |
| CRY-4.2 | Не дефолтный пароль KDF | 🔴 | Пароль шифрования = дефолт (напр. `changeme`) | Сильный уникальный ключ из vault |
| CRY-4.3 | Не статическая соль | 🟠 | Захардкоженная соль в коде (напр. `b"static_salt_value"`) | Случайная соль на запись |
| CRY-4.4 | Современный алгоритм | 🟠 | DES/RC4/ECB-режим | AES-GCM / ChaCha20-Poly1305 / Fernet |
| CRY-4.5 | Authenticated encryption | 🟠 | Шифрование без аутентификации (нет MAC) | AEAD-режимы |
| CRY-4.6 | Уникальный IV/nonce | 🟠 | Переиспользование IV | Случайный IV на каждое шифрование |
| CRY-4.7 | Стратегия ре-шифрования | 🟠 | Нельзя сменить ключ без потери доступа | Механизм re-key по каждому хранилищу |
| CRY-4.8 | TLS в транзите | 🟠 | Данные/RPC по HTTP | HTTPS/TLS везде |

> ⚠️ **Урок из практики (Critical):** приватные ключи кошельков зашифрованы Fernet-ключом, выведенным из
> **дефолтного пароля + захардкоженной в коде статической соли** → шифрование не даёт
> защиты at-rest. Плюс: у части сетей **нет ре-шифрования** — включить шифрование на заполненном
> проде нельзя без миграции (иначе ключи станут нерасшифровываемыми). Проектируй re-key заранее.

## 5. KDF, хеширование, случайность

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| CRY-5.1 | Пароли: правильный KDF | 🔴 | MD5/SHA без соли для паролей | Argon2id/bcrypt/scrypt/PBKDF2 |
| CRY-5.2 | Достаточно итераций/памяти | 🟡 | Слишком мало итераций PBKDF2 | ≥ 600k PBKDF2 / рекоменд. Argon2 |
| CRY-5.3 | CSPRNG для секретов | 🟠 | `random`/`Math.random` для токенов | `secrets`/`crypto.randomBytes` |
| CRY-5.4 | Timing-safe сравнение | 🟠 | `==` для секретов/MAC | `hmac.compare_digest`/`crypto.timingSafeEqual` |
| CRY-5.5 | Хеш для integrity | 🟡 | MD5/SHA1 для целостности | SHA-256+ |
| CRY-5.6 | Достаточная энтропия токенов | 🟠 | Короткие/предсказуемые токены | ≥ 128 бит |
| CRY-5.7 | Нет самодельной крипто | 🟠 | Custom encryption/подпись | Проверенные библиотеки |

## 6. Скрытые эндпоинты подписей

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| CRY-6.1 | Нет подписей без бизнес-валидации | 🔴 | `include_in_schema=False`, «No validations», «bypass» | Все подписи через бизнес-валидацию |
| CRY-6.2 | Private API защищён не только токеном | 🔴 | Статический токен = single point of failure | IP allowlist + mTLS + audit log |
| CRY-6.3 | Audit log генераций подписей | 🟠 | Нет записи каждой подписи | Логировать wallet/amount/timestamp |
| CRY-6.4 | Служебные подписи закрыты снаружи | 🔴 | Эндпоинт подписи доступен из интернета | Только внутренняя сеть |

## Быстрые команды проверки

```bash
# Ключи в коде/истории
rg "0x[0-9a-fA-F]{64}" 
git log --all -p -G "0x[0-9a-fA-F]{40,}" -- '*.py' '*.env*' '*.ts'

# Слабая крипто
rg -i "md5|sha1\b|DES|RC4|ECB|Random\(\)|Math\.random" 
rg -i "hashlib\.(md5|sha1)|CryptoJS" 

# Небезопасное сравнение
rg "==\s*.*(signature|token|key|hmac|mac)" 

# KDF/шифрование
rg -i "PBKDF2|Argon2|bcrypt|scrypt|Fernet|AES|salt\s*=\s*b?['\"]" 
rg -i "salt\s*=\s*b['\"]" --type py    # статическая соль

# CSPRNG
rg "import random|random\.(random|randint|choice)" --type py    # для секретов — плохо
```
