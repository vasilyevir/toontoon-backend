# 01 — Аутентификация

> Проверка всех механизмов подтверждения личности: JWT, OAuth/OIDC, wallet-подписи, пароли, MFA,
> защита от перебора. Аутентификация — первый рубеж; её обход часто = полный account takeover.

**Легенда:** 🔴 Critical · 🟠 High · 🟡 Medium · 🟢 Low · ⚪ Info
**OWASP:** A07:2021 (Identification & Auth Failures) · **ASVS:** V2 · **CWE:** 287, 384, 307, 798

## 1. JWT-токены

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| AUTH-1.1 | Lifetime access/refresh | 🟠 | Access > 15 мин, refresh > 7 дней. Для финансов: access 5–15 мин, refresh 1–7 дней | Короткий access + ротируемый refresh |
| AUTH-1.2 | Ротация refresh-токенов | 🟠 | `ROTATE_REFRESH_TOKENS: False` → утёкший refresh = долгий доступ | Включить ротацию при каждом refresh |
| AUTH-1.3 | Blacklist при ротации | 🟠 | `BLACKLIST_AFTER_ROTATION: False` → старые refresh живут | Blacklist старых токенов |
| AUTH-1.4 | Алгоритм подписи | 🟡 | HS256 c общим `SECRET_KEY`; **`alg: none`**; confusion RS256→HS256 | Явно фиксировать алгоритм; RS256/EdDSA предпочтительнее |
| AUTH-1.5 | Проверка `is_active`/`is_blocked` | 🔴 | `get_user_from_token()` не проверяет `is_active`, `is_blocked`, `is_deleted` | Проверять статус на каждом запросе |
| AUTH-1.6 | Инвалидация при logout | 🟠 | Удаление cookie ≠ инвалидация на сервере | Token blacklist / короткий TTL + серверный store |
| AUTH-1.7 | Инвалидация при смене пароля | 🟠 | Активные сессии не отзываются | Версия токена / `token_version` в claim |
| AUTH-1.8 | Инвалидация при смене кошелька/email | 🟠 | Старые JWT привязаны к старому идентификатору | Пересоздание claim-подписей, отзыв старых |
| AUTH-1.9 | Проверка `exp`, `nbf`, `iat` | 🟠 | Просроченные токены принимаются | Строгая проверка времени с leeway ≤ 60с |
| AUTH-1.10 | Секрет не дефолтный | 🔴 | `SECRET_KEY = "dev"`/`"changeme"` fallback | Fail-closed: нет секрета → не стартовать |
| AUTH-1.11 | Проверка `aud`/`iss` | 🟡 | Токен для другого сервиса принимается | Валидировать audience и issuer |
| AUTH-1.12 | Чувствительные данные в payload | 🟡 | Пароль/PII/ключи в claims (JWT не шифрован!) | Только идентификаторы; при нужде — JWE |

> ⚠️ **`alg: none` / algorithm confusion** — классический обход: атакующий меняет `alg` на `none`
> или подменяет RS256 на HS256, используя публичный ключ как HMAC-секрет. Библиотека должна
> принимать **строго ожидаемый** алгоритм (`algorithms=["RS256"]`), не читать `alg` из токена.

## 2. OAuth / OIDC

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| AUTH-2.1 | Верификация подписи ID-токена | 🔴 | `jwt.decode(..., options={"verify_signature": False})` → **Account Takeover** | Проверять подпись по JWKS провайдера |
| AUTH-2.2 | Верификация `aud` | 🟠 | Токен от другого приложения принимается | Сверять с своим client_id |
| AUTH-2.3 | Верификация `iss` | 🟠 | Любой issuer | Только `accounts.google.com` / `appleid.apple.com` |
| AUTH-2.4 | Проверка `exp` | 🟠 | Просроченные токены принимаются | Строгая проверка |
| AUTH-2.5 | State parameter (CSRF) | 🟡 | Нет `state` → CSRF в OAuth flow | Криптослучайный `state`, привязка к сессии |
| AUTH-2.6 | PKCE для публичных клиентов | 🟠 | SPA/mobile без PKCE → перехват `code` | `code_challenge`/`code_verifier` (S256) |
| AUTH-2.7 | Redirect URI валидация | 🟠 | Open redirect; `window.location.origin` на клиенте | Строгий whitelist точных URI |
| AUTH-2.8 | Проверка `is_active` после входа | 🟠 | Заблокированный входит через OAuth | Проверять статус локального аккаунта |
| AUTH-2.9 | Привязка соц-аккаунта к email | 🟠 | Account linking по непроверенному email → takeover | Требовать verified email / явное подтверждение |
| AUTH-2.10 | Nonce (replay ID-токена) | 🟡 | Нет `nonce` → повтор ID-токена | Одноразовый `nonce`, сверка |

## 3. Wallet-аутентификация (Web3)

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| AUTH-3.1 | Верификация подписи | 🔴 | Подпись кошелька не проверяется криптографически | `ecrecover` / `is_base58check` + сверка адреса |
| AUTH-3.2 | Nonce одноразовый | 🟠 | Nonce не инвалидируется после использования → replay | Удалять/помечать использованным атомарно |
| AUTH-3.3 | Nonce TTL | 🟡 | > 10 мин → окно replay | 3–5 мин |
| AUTH-3.4 | Формат сообщения | 🟡 | Свободный формат без контекста | EIP-4361 (SIWE) / EIP-191 / TIP-191 |
| AUTH-3.5 | Привязка к домену | 🟡 | Нет domain → фишинг подписывает от вашего имени | `domain` в SIWE-сообщении |
| AUTH-3.6 | Chain ID в сообщении | 🟡 | Cross-chain replay | Включить `chainId` |
| AUTH-3.7 | Timestamp / expiry | 🟡 | Подпись живёт вечно | `issuedAt` + `expirationTime` |
| AUTH-3.8 | Адрес валиден по checksum | 🟡 | Некорректный/подменённый адрес | Валидация формата и контрольной суммы |

## 4. Password-аутентификация

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| AUTH-4.1 | Хеширование паролей | 🔴 | MD5/SHA1/SHA256 без соли; plaintext | Argon2id / bcrypt(≥12) / scrypt / PBKDF2 |
| AUTH-4.2 | Политика паролей | 🟡 | Нет минимума | Длина ≥ 8–12, проверка по breach-листам (HIBP) |
| AUTH-4.3 | User enumeration | 🟡 | `"User not found"` vs `"Invalid credentials"` | Единое сообщение для всех случаев |
| AUTH-4.4 | Timing attack | 🟡 | Быстрый ответ для несуществующих юзеров | Dummy-хеш даже при отсутствии юзера |
| AUTH-4.5 | Пароль в логах | 🟠 | `request.body` логируется на login/register | Исключить пароль из логирования (redaction) |
| AUTH-4.6 | Пароль в URL/GET | 🟠 | Пароль в query string → логи/history | Только POST body |
| AUTH-4.7 | Смена пароля требует старый | 🟡 | Смена без подтверждения текущего | Требовать текущий пароль / re-auth |
| AUTH-4.8 | Отзыв сессий при смене | 🟠 | Старые сессии живут | Инвалидация всех сессий (см. AUTH-1.7) |

## 5. MFA / 2FA

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| AUTH-5.1 | MFA на критичных операциях | 🟠 | Вывод средств, смена кошелька/пароля без 2-го фактора | Требовать MFA/re-auth |
| AUTH-5.2 | TOTP-секрет зашифрован | 🟡 | `totp_secret` plaintext в БД → обход 2FA при дампе | Шифровать (Fernet/KMS) |
| AUTH-5.3 | Rate limiting на 2FA | 🟠 | Перебор 6-значного кода | Лимит попыток + блокировка |
| AUTH-5.4 | TOTP window | 🟡 | Слишком широкое окно (`valid_window` > 1) | ±1 шаг (±30с) |
| AUTH-5.5 | Backup-коды | 🟡 | Низкая энтропия (8 hex), не одноразовые | ≥ `token_hex(10)`, одноразовые, хешированные |
| AUTH-5.6 | 2FA bypass через recovery | 🟠 | Сброс пароля обходит 2FA | Recovery не должен снимать 2FA автоматически |
| AUTH-5.7 | Enrollment protection | 🟡 | Можно привязать чужой MFA | Подтверждение владения перед активацией |

## 6. Защита от перебора и enumeration

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| AUTH-6.1 | Rate limiting на login | 🟠 | Нет лимита → brute-force | 5–10 попыток/мин на IP + аккаунт |
| AUTH-6.2 | Account lockout / CAPTCHA | 🟠 | После N неудач нет реакции | Временная блокировка / экспоненциальная задержка / CAPTCHA |
| AUTH-6.3 | Rate limiting на register | 🟡 | Массовая регистрация → манипуляция рефералкой | Лимит + CAPTCHA |
| AUTH-6.4 | Rate limiting на reset | 🟡 | Email flooding | 3–5/час на email |
| AUTH-6.5 | Обход лимита по заголовку | 🟠 | Rate-limit по `X-Forwarded-For` → подмена IP снимает лимит | Использовать доверенный `CF-Connecting-IP` / real IP от прокси |
| AUTH-6.6 | Concurrent session limit | 🟡 | 1000+ активных сессий у одного юзера | Лимит активных refresh-токенов |
| AUTH-6.7 | Device fingerprint / binding | 🟡 | Токен работает с любого устройства/IP | Привязка к контексту, детект аномалий |

> ⚠️ **Урок из практики:** rate-limit на эндпоинте логина обходился подстановкой `X-Forwarded-For` →
> неограниченный брутфорс. За доверенным прокси бери реальный IP из проверенного заголовка, а не из
> произвольного пользовательского.

## 7. Account recovery

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| AUTH-7.1 | Одноразовый токен сброса | 🟠 | Токен многоразовый / не инвалидируется | Одноразовый, инвалидация после использования |
| AUTH-7.2 | TTL токена сброса | 🟡 | Живёт долго | TTL ≤ 15 мин |
| AUTH-7.3 | Энтропия токена | 🟠 | Предсказуемый/короткий токен | `secrets.token_urlsafe(32)` |
| AUTH-7.4 | Токен не в Referer/логах | 🟡 | Токен в URL утекает в Referer/аналитику | Одноразовое использование + короткий TTL |
| AUTH-7.5 | Уведомление о смене | 🟡 | Нет письма о сбросе пароля | Email-уведомление о критичных изменениях |
| AUTH-7.6 | Recovery не enumerate | 🟡 | Разный ответ для существующего/нет email | «Если email существует, письмо отправлено» |

## 8. Межсервисная аутентификация

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| AUTH-8.1 | Нет дефолтного service-key | 🔴 | Backend-key = дефолт на всё (напр. `changeme`) | `openssl rand -hex 32`, уникальный |
| AUTH-8.2 | Timing-safe сравнение | 🟠 | `key == provided` (уязвимо к timing) | `hmac.compare_digest()` |
| AUTH-8.3 | Fail-closed при отсутствии ключа | 🟠 | Нет env → работает на дефолте | Нет ключа → 403/падение |
| AUTH-8.4 | Правильная переменная окружения | 🟠 | Читается не та переменная (`_BTC_` захардкожено) | Единое согласованное имя |
| AUTH-8.5 | mTLS / IP allowlist на service API | 🟠 | Только статический токен = single point of failure | mTLS + IP allowlist + audit log |
| AUTH-8.6 | Служебные эндпоинты закрыты снаружи | 🔴 | `/internal`, `/service/*`, `/webhook` на публичном домене | Блок на reverse-proxy, только внутр. сеть |

> ⚠️ **Урок из практики (Critical):** служебный эндпоинт с дефолтным ключом был доступен из
> интернета и отдавал ключ шифрования кошельков. Три меры: (1) fail-closed уникальный ключ,
> (2) `hmac.compare_digest`, (3) блок пути на reverse-proxy снаружи.

## Быстрые команды проверки

```bash
# Отключённая верификация подписи (OAuth/JWT)
rg "verify_signature.*False|verify=False|options=\{.*verify" --type py

# Дефолтные секреты
rg -i "secret_key.*=.*['\"](dev|changeme|secret|password)" 
rg -i "(backend_key|api_key|service_key)\s*=\s*['\"](dev|changeme|secret|test|admin)"

# Небезопасное сравнение ключей (не timing-safe)
rg "backend.?key.*==|api.?key.*==|token.*==.*request" --type py

# Отсутствие rate limiting
rg -i "limiter|ratelimit|throttle" --type py || echo "нет rate-limit"

# is_active не проверяется в аутентификации
rg -A10 "def get_user_from_token|def authenticate" --type py | rg -v "is_active|is_blocked"
```

См. полный набор в [27 — Команды быстрой проверки](./27-quick-commands.md).
