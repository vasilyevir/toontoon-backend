## 1. Инвентаризация и минимизация PII

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PRIV-1.1 | Карта PII | 🟡 | Неизвестно, где какие персональные данные | Data inventory / data map |

## 3. Доступ и утечки

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PRIV-3.1 | Публичные хранилища с PII | 🔴 | Публичный бакет с фото/данными | Приватный доступ (см. [20](./20-cloud-security.md)) |
| PRIV-3.2 | IDOR на PII | 🔴 | Доступ к чужим персональным данным | Проверка владения (см. [02](./02-authorization-idor.md)) |
| PRIV-3.3 | PII в логах | 🟠 | Email/телефон/адрес в логах | Redaction (см. [22](./22-logging-monitoring.md)) |
| PRIV-3.4 | PII в URL | 🟡 | Идентификаторы в query → логи/Referer | Не передавать PII в URL |
| PRIV-3.5 | PII в аналитике/трекерах | 🟠 | Утечка в сторонние сервисы | Фильтрация до отправки |
| PRIV-3.6 | Enumeration PII | 🟡 | Перебор пользователей/данных | UUID, лимиты, 404 |
| PRIV-3.7 | Экспорт данных без лимита | 🟡 | Массовый дамп PII через API | Лимиты + аудит экспорта |

> ⚠️ **Урок из практики:** публичный бакет объектного хранилища раскрыл тысячи UUID пользователей и их фото — прямой
> GDPR-инцидент. PII-хранилища всегда приватные, доступ — только авторизованный/presigned.

## 4. Права субъектов данных (GDPR)

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PRIV-4.1 | Право на доступ | 🟡 | Нет механизма выгрузки данных субъекта | Data export |
| PRIV-4.2 | Право на удаление | 🟡 | Нельзя удалить данные (right to be forgotten) | Механизм удаления/анонимизации |
| PRIV-4.3 | Право на исправление | 🟢 | Нельзя исправить данные | Механизм редактирования |
| PRIV-4.4 | Портируемость | 🟢 | Нет экспорта в машиночитаемом формате | Export (JSON/CSV) |
| PRIV-4.5 | Breach notification | 🟡 | Нет процедуры уведомления об утечке | Процедура (72ч по GDPR) |
| PRIV-4.6 | Обработчики/DPA | 🟢 | Нет учёта суб-обработчиков | Реестр + DPA |

## 5. Хранение, удаление, retention

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PRIV-5.1 | Retention policy | 🟡 | Данные хранятся вечно | Политика хранения по типам |
| PRIV-5.2 | Автоудаление устаревшего | 🟢 | Нет TTL/очистки | Автоматическая очистка |
| PRIV-5.3 | Каскадное удаление | 🟡 | Осиротевшие PII при удалении аккаунта | Полное удаление связанного |
| PRIV-5.4 | Удаление из бэкапов | 🟢 | PII остаётся в старых бэкапах | Учёт retention бэкапов |
| PRIV-5.5 | Soft delete не оставляет PII | 🟡 | «Удалённые» данные остаются читаемыми | Анонимизация при soft delete |

## 6. Специфика (PCI/финансы)

| # | Проверка | Крит. | Что искать / вектор | Как исправить |
|---|----------|-------|---------------------|---------------|
| PRIV-6.1 | Нет хранения CVV | 🔴 | CVV/CVC сохраняется | Никогда не хранить CVV |
| PRIV-6.2 | Маскирование PAN | 🟠 | Полный номер карты в логах/UI | Маскировать (первые 6/последние 4) |
| PRIV-6.3 | Скоуп PCI минимален | 🟡 | Карты проходят через свою систему | Провайдер/токенизация, вывод из скоупа |
| PRIV-6.4 | KYC/AML данные защищены | 🟠 | Документы KYC в открытом доступе | Строгий доступ + шифрование |

## Быстрые команды проверки

```bash
# PII-поля в моделях
rg -i "email|phone|passport|ssn|address|full_name|birth|card|iban|kyc" --type py

# PII в логах
rg -i "logger.*(email|phone|card|passport|ssn)" 

# Публичные хранилища
rg -i "public-read|allUsers|BlockPublicAccess"

# Хранение CVV/карт (не должно быть)
rg -i "cvv|cvc|card_number|pan\b|full_pan"

# Удаление/retention
rg -i "on_delete|CASCADE|soft.?delete|retention|ttl|expire" --type py
```
